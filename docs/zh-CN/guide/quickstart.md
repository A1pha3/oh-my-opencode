## 什么是 Oh My OpenCode？

Oh My OpenCode 是一个 **OpenCode 插件**，它将普通的 AI 助手转换成一个**专业的开发团队**。

### 🤔 用一个比喻理解

想象你是一个项目经理，手头有一支技术精湛的开发团队：

- **Prometheus（规划师）**：精通战略规划，擅长理解复杂需求
- **Oracle（架构师）**：技术顾问，解决复杂架构问题
- **Librarian（研究员）**：精通文档和开源代码研究
- **Frontend Engineer（前端专家）**：UI/UX 设计专家
- **Explore（代码侦探）**：快速搜索和理解代码库
- **Junior（实干家）**：专注执行任务，不偷懒、不半途而废

Oh My OpenCode 就是这些"团队成员"的**管理者**，根据任务类型自动分配给最合适的人。

### 🎯 它能为你做什么？

- **🔨 从零构建功能**：你说"添加用户认证"，它理解需求、探索代码库、实现代码、运行测试、持续工作直到完成
- **🐛 修复 Bug**：描述问题或粘贴错误，它分析代码、定位根因、实施修复
- **🗺️ 导航任何代码库**：问任何关于你的代码库的问题，它保持对整个项目结构的感知
- **⚡ 自动化繁琐任务**：修复 lint 问题、解决合并冲突、编写发布说明——一条命令搞定

## 为什么需要它？

### ❌ 传统 AI 助手的问题

你可能已经用过 ChatGPT、Claude 或其他 AI 工具。它们的问题是什么？

```
用户："帮我添加用户登录功能"

AI 助手：
1. 生成代码 ← 不知道你的项目结构
2. 提供代码 ← 可能不符合你的编码风格
3. 等待反馈 ← 你手动修复问题
4. 继续生成 ← 重复这个循环
```

**问题**：
- ❌ 不理解你的代码库约定
- ❌ 需要你反复指导
- ❌ 半途而废，"差不多就行了"
- ❌ 生成质量参差不齐

### ✅ Oh My OpenCode 的解决方案

```
用户："帮我添加用户登录功能"

Oh My OpenCode：
1. [Explore 后台运行] 快速分析项目结构
2. [Librarian 后台运行] 搜索最佳实践
3. [Atlas 调度] 理解需求，制定计划
4. [Junior 执行] 按照你的约定编写代码
5. [Frontend 优化] 美化 UI 组件
6. [验证] 运行测试、检查 lint、验证功能
7. [完成] 直到所有任务完成才停止
```

**优势**：
- ✅ 自动理解你的代码库模式
- ✅ 不需要你手动指导
- ✅ 强制完成所有任务
- ✅ 生成专业级别的代码

## 安装步骤

### 📋 前置条件

在开始之前，你需要：

- ✅ **已安装 OpenCode**（版本 >= 1.0.150）
  - 安装指南：https://opencode.ai/docs
- ✅ **至少一个 AI 服务订阅**：
  - Claude Pro/Max
  - OpenAI/ChatGPT Plus
  - Google Gemini
  - GitHub Copilot
  - OpenCode Zen
  - Z.ai Coding Plan

> 💡 **重要提示**：Sisyphus 代理（主要的协调器）强烈推荐使用 Opus 4.5 模型。使用其他模型可能会显著降低体验质量。

### 🚀 方式一：让 AI 帮你安装（推荐）

这是最简单的方式，完全不需要你自己操作。

**将以下提示词复制到你的 AI 工具（Claude Code、Cursor、AmpCode 等）：**

```
请按照这里的说明安装并配置 oh-my-opencode：
https://github.com/code-yeongyu/oh-my-opencode/blob/dev/docs/guide/installation.md
```

**AI 助手会：**
1. 检查你是否已安装 OpenCode
2. 运行交互式安装程序
3. 根据你的订阅情况配置模型
4. 指导你完成身份验证
5. 验证安装是否成功

### 🛠️ 方式二：手动安装（高级用户）

如果你想手动控制整个过程：

```bash
# 运行交互式安装程序
bunx oh-my-opencode install

# 或者使用 npx
npx oh-my-opencode install
```

**安装过程：**

1. **提供者选择**：选择你拥有的 AI 服务（Claude、ChatGPT、Gemini 等）
2. **API 密钥输入**：输入所选提供者的 API 密钥
3. **配置文件生成**：自动生成 `oh-my-opencode.json` 配置文件
4. **插件注册**：在 OpenCode 设置中自动注册插件

**安装选项：**

```bash
# 非交互模式（适合 CI/CD 环境）
bunx oh-my-opencode install --no-tui --claude=yes --gemini=yes

# 带详细日志
bunx oh-my-opencode install --verbose
```

### ✅ 验证安装

安装完成后，运行以下命令验证：

```bash
# 检查 OpenCode 版本
opencode --version  # 应该 >= 1.0.150

# 查看插件是否已注册
cat ~/.config/opencode/opencode.json  # 应该包含 "oh-my-opencode"
```

### 🔐 配置身份验证

根据你选择的 AI 提供者，你需要完成身份验证：

#### Anthropic (Claude)

```bash
opencode auth login
# 在交互式终端中选择：
# Provider: Anthropic
# Login method: Claude Pro/Max
# 按照浏览器中的指引完成 OAuth 流程
```

#### OpenAI (ChatGPT)

```bash
opencode auth login
# 选择 Provider: OpenAI
# 输入 API 密钥或完成 OAuth
```

#### Google Gemini

首先安装 `opencode-antigravity-auth` 插件：

```json
{
  "plugin": [
    "oh-my-opencode",
    "opencode-antigravity-auth@latest"
  ]
}
```

然后在 `oh-my-opencode.json` 中配置模型：

```json
{
  "agents": {
    "multimodal-looker": { "model": "google/antigravity-gemini-3-flash" }
  }
}
```

最后完成身份验证：

```bash
opencode auth login
# 选择 Google → OAuth with Google (Antigravity)
# 在浏览器中完成登录
```

## 三种使用方式

Oh My OpenCode 提供三种不同的工作模式，从"完全手动"到"完全自动"，你可以根据任务复杂度选择。

### 🌟 方式一：Ultrawork 模式（懒人必备）

> **最适合**：日常开发、中等到复杂任务、懒得详细说明

**使用方法：**在提示词中包含 `ultrawork` 或简写 `ulw`

```
ulw 为我的 Next.js 应用添加用户认证功能
```

**系统会自动：**

1. **探索代码库**：Explore 代理在后台快速分析你的项目结构
2. **研究最佳实践**：Librarian 代理搜索官方文档和开源实现
3. **理解现有模式**：识别你的编码风格和约定
4. **实现功能**：按照你的约定编写代码
5. **验证结果**：运行测试、检查 lint 错误
6. **持续工作**：如果发现问题，自动修复，直到所有任务完成

**特点：**
- ✅ 你什么都不用想，代理会思考
- ✅ 自动处理所有细节
- ✅ 并行运行多个代理，像真实团队
- ✅ 不停止直到完成

**使用场景：**
- 添加新功能（中等复杂度）
- 重构模块
- 修复复杂 Bug
- 编写测试

### 🎯 方式二：Prometheus 规划模式（精确控制）

> **最适合**：多天项目、关键生产变更、需要完整决策记录

**使用方法：**按 **Tab** 键切换到 Prometheus（规划器）模式

**工作流程：**

#### 第 1 步：采访

Prometheus 会作为你的私人顾问，通过智能提问来明确需求：

```
用户："我想添加用户认证"

Prometheus：
1. 让我先分析一下你的项目... [Explore 在后台运行]
2. 我发现你正在使用 Next.js，有现成的认证组件吗？
3. 你希望使用 NextAuth.js 还是自定义实现？
4. 支持哪些登录方式？邮箱、Google、GitHub？
5. 是否需要用户角色权限系统？
```

#### 第 2 步：生成计划

需求明确后，Prometheus 生成详细的工作计划：

**计划文件：`.sisyphus/plans/{name}.md`**

```markdown
# 用户认证功能实现计划

## 背景与目标
- 当前使用 Next.js 14
- 需要添加邮箱 + Google 登录
- 支持基础角色系统（用户、管理员）

## 任务清单

- [ ] 1. 安装和配置 NextAuth.js
  - 使用你现有的环境变量模式
  - 配置 GitHub OAuth
  - 配置 Google OAuth

- [ ] 2. 创建用户数据模型
  - 在 `lib/db/schema.prisma` 中添加 User 表
  - 运行数据库迁移

- [ ] 3. 实现登录页面
  - 参考现有的 `login/page.tsx` 风格
  - 添加邮箱登录表单
  - 添加 Google 登录按钮

- [ ] 4. 实现 API 路由
  - 创建 `app/api/auth/[...nextauth]/route.ts`
  - 实现会话管理

- [ ] 5. 添加权限检查
  - 创建 `lib/auth.ts` 工具函数
  - 在需要登录的页面中集成

- [ ] 6. 编写测试
  - 测试登录流程
  - 测试权限检查

## 验收标准
- [ ] 用户可以通过邮箱登录
- [ ] 用户可以通过 Google 登录
- [ ] 未登录用户无法访问受保护页面
- [ ] 所有测试通过
- [ ] 没有 lint 错误
```

#### 第 3 步：执行

当计划准备好后，输入 `/start-work` 命令：

```bash
/start-work
```

**Atlas（协调器）接管：**
1. 读取计划文件
2. 按顺序执行每个任务
3. 将任务委托给合适的代理（Frontend 做 UI、Oracle 做架构）
4. 验证每个任务完成
5. 持续工作直到所有任务完成
6. 生成最终报告

**特点：**
- ✅ 完整的决策记录
- ✅ 可验证的验收标准
- ✅ 可以随时中断和恢复
- ✅ 适合跨天项目

### 💬 方式三：直接对话（快速修复）

> **最适合**：简单任务、快速修复、单文件变更

**使用方法：**直接描述你的需求

```
修复 LoginButton.tsx 中的移动端布局问题
```

**系统会：**
1. 读取相关文件
2. 理解问题
3. 修复代码
4. 验证修改

**使用场景：**
- 修复简单的 Bug
- 单个文件的代码调整
- 添加小的功能
- 代码格式化或 lint 修复

## 常见新手问题

### Q1: 必须使用 Ultrawork 模式吗？

**A:** 不是。你可以选择任意一种模式：

- **日常开发**：Ultrawork 最方便
- **复杂项目**：Prometheus 规划更可控
- **快速修复**：直接对话最快

### Q2: 会很贵吗？

**A:** 取决于你的使用方式。Oh My OpenCode 会自动优化成本：

- 简单任务使用廉价模型（Haiku、Flash）
- 复杂推理使用高级模型（Opus、GPT-5.2）
- 并行执行减少总体时间

**提示**：在配置文件中设置类别模型，可以进一步优化成本。

### Q3: 生成的代码质量如何？

**A:** 系统的设计目标是"不可区分"：

- 遵循你的代码库约定
- 不需要额外清理
- 测试实际测试正确的事情
- 适当的错误处理
- 只在必要时添加注释

如果一眼就能看出是 AI 写的代码，说明系统需要改进。

### Q4: 可以中途停止吗？

**A:** 可以。Ultrawork 模式下：
- 按 `Ctrl+C` 中断
- 下次继续时，系统会自动恢复

Prometheus 模式下：
- 工作进度保存在 `.sisyphus/boulder.json`
- 随时可以随时恢复：`/start-work`

### Q5: 如果任务失败了怎么办？

**A:** 系统会自动处理：

1. **验证失败**：如果测试不通过，自动修复
2. **Lint 错误**：自动修复常见的 lint 问题
3. **运行时错误**：分析错误、定位根因、实施修复
4. **无法解决**：升级到 Oracle（高级顾问）或向你报告

**不会半途而废。**

### Q6: 可以多个项目使用吗？

**A:** 可以。有两种配置方式：

1. **全局配置**：`~/.config/opencode/oh-my-opencode.json`（所有项目共享）
2. **项目配置**：`.opencode/oh-my-opencode.json`（当前项目特有）

项目配置优先级更高。

### Q7: 需要自己编写配置文件吗？

**A:** 不需要。安装程序会自动生成：

```bash
bunx oh-my-opencode install  # 自动生成配置
```

如果你想自定义配置，请参考 [配置指南](../configuration/complete-guide.md)。
